A coding agent where the code already is.

OpenFX runs in the terminal you already have open, against the checkout you are already in. It reads files, runs commands, edits code and opens pull requests — and asks before it does anything it cannot take back.

What makes it different

Most of these follow from one decision: it is a native binary that runs locally, not a service you send your repository to.

  • One static binary

    No runtime to install, no interpreter, no node_modules. The package is a single executable linked against musl, so it runs on any host of the right architecture and starts fast enough to use casually.

  • It asks before it acts

    Reads and in-worktree edits run untouched. Anything destructive or outward-facing stops and asks, and the permission you give is scoped to what you were shown — not remembered as blanket consent for next time.

  • Your own model provider

    Vercel AI Gateway, a ChatGPT subscription or a Grok subscription — chosen with openfx login, and stored on your machine. No account with us, because there is no us to have an account with.

  • Subagents and skills

    Long jobs fan out to subagents with their own context, so the main conversation stays readable. Skills are ordinary directories in your repository or your home directory, not a registry someone else controls.

  • Speaks MCP and ACP

    An MCP client for your existing tool servers, and an ACP server so editors that speak it can drive OpenFX directly instead of shelling out to it.

  • Everything stays local

    Sessions, history, settings and credentials live in ~/.openfx on your disk. The only thing that leaves your machine is the request you asked it to make.

How to install it

One line on Debian and Ubuntu, and the same script handles macOS and other Linux by fetching the release build instead.

Anywhere

Detects the host: adds the APT repository where that works, and otherwise downloads the release for your platform and verifies its checksum. 

curl -fsSL https://apt.stack256.org/openfx/install.sh | sh

Debian and Ubuntu, by hand

One signed APT source serves every Stack256 package, so it is one line and one key however many of them you run. 

# add the repository, once
curl -fsSL https://apt.stack256.org/stack256-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/stack256-archive-keyring.gpg > /dev/null

echo "deb [signed-by=/etc/apt/keyrings/stack256-archive-keyring.gpg] \
https://apt.stack256.org stable main" \
  | sudo tee /etc/apt/sources.list.d/stack256.list

sudo apt update && sudo apt install openfx

No root needed. The script installs into ~/.local/bin unless a system directory is already yours to write to. Only the APT route asks for a password, and not for OpenFX’s sake — adding a system package repository always does.

Keeping it current

Which command depends on how you installed it, and OpenFX knows which one you used.

Installed from apt sudo apt update && sudo apt upgrade, with everything else on the host. openfx upgrade deliberately refuses here and says so: replacing a package-managed binary behind dpkg’s back leaves the two disagreeing about what is installed.
Installed from the tarball openfx upgrade

What it needs

Host Linux or macOS. No service, no daemon, no root once installed
Architectures amd64 and arm64, on both
Runtime None — one statically linked binary
Model access Vercel AI Gateway, a ChatGPT subscription, or a Grok subscription — chosen with openfx login
State ~/.openfx, on your own disk
Terminal Any reasonably modern one. openfx ask runs noninteractively for scripts and CI
Licence Open source — every line readable in the repository

Have a look at the code

OpenFX began as a fork of vercel-labs/fx and has since diverged. If something here is wrong, or missing, the issue tracker is the right place for it.
